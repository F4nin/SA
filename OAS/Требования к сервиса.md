Ниже — полные требования для трёх сервисов: **libraryService**, **matchService** (киберспортивная платформа) и **orderService**. Они сформулированы как переиспользуемые спецификации: бизнес-контекст, роли, сущности, функциональные и нефункциональные требования, соглашения по данным.

Каждый блок можно использовать как ТЗ для разработки OAS-контракта или как документацию для команды.

---

# 1. libraryService — API библиотеки

## Бизнес-контекст

`libraryService` — API автоматизации городской библиотеки. Через него внешние клиенты и внутренние сервисы работают с каталогом книг. Система предоставляет:

- просмотр каталога книг публичным пользователям;
- управление каталогом авторизованным сотрудникам/администраторам.

## Роли

| Роль | Права |
| --- | --- |
| Публичный пользователь | Без авторизации просматривает список книг и одну книгу |
| Администратор (books:write) | Создаёт, полностью обновляет, частично обновляет и удаляет книги |

## Сущности

### Book (книга)

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `id` | string (`^[0-9]+$`) | Да | Идентификатор, присваивается сервером, readOnly |
| `title` | string | Да | Название книги |
| `author` | string | Да | Автор |
| `isbn` | string (pattern ISBN) | Да | Международный стандартный номер книги |
| `publicationYear` | integer, `minimum: 1000`, `maximum: 2100` | Нет | Год издания |
| `genre` | string | Нет | Жанр |
| `totalCopies` | integer, `minimum: 0`, readOnly | Нет | Всего экземпляров в библиотеке |
| `availableCopies` | integer, `minimum: 0`, readOnly | Нет | Доступно для выдачи |

`totalCopies` и `availableCopies` — учётные поля сервера. Пользователь не может их менять через публичные операции.

## Операции

| Ресурс | Метод | Роль | Успех | Ошибки |
| --- | --- | --- | --- | --- |
| `/books` | GET | Публичный | 200 | 400, 500 |
| `/books` | POST | Админ | 201 | 400, 401, 500 |
| `/books/{id}` | GET | Публичный | 200 | 400, 404, 500 |
| `/books/{id}` | PUT | Админ | 200 | 400, 401, 404, 500 |
| `/books/{id}` | PATCH | Админ | 200 | 400, 401, 404, 500 |
| `/books/{id}` | DELETE | Админ | 200 | 400, 401, 404, 500 |

## Пагинация и фильтрация

- `GET /books`:
  - `limit`: integer, `minimum: 1`, `maximum: 100`, `default: 20`
  - `offset`: integer, `minimum: 0`, `default: 0`
- Верхнеуровневый ответ коллекции — объект `BookList` с полем `items`, а не голый массив [source:1s5r4vz4tbmt6a0pnxnr].

## Соглашения по данным

- Идентификаторы строковые.
- Временные метки не используются в модели книги.
- ISBN проверяется паттерном.
- Количественные поля неотрицательные.
- Модель запроса (`RequestBook`) не содержит `id`; модель ответа (`ResponseBook`) содержит `id`.
- Частичное обновление (`PATCH`) не требует обязательных полей.

## Безопасность

- Схема: OAuth2.
- Scopes:
  - `books:read` — просмотр каталога (в реализации просмотр публичный, `security: []`);
  - `books:write` — создание, изменение, удаление.
- Публичные методы: `GET /books` и `GET /books/{id}` — `security: []`.
- Для защищённых методов обязателен ответ `401 Unauthorized` [source:ygmgyjncoevwts67ikmx].

# 2. matchService — API киберспортивной платформы

## Бизнес-контекст

Сервис киберспортивных матчей и игровых событий. Работает для двух аудиторий:

- клиенты — читают расписание и результаты;
- администраторы — управляют матчами.

## Роли

| Роль | Права |
| --- | --- |
| Клиент (matches:read) | Просмотр списка матчей и одного матча |
| Администратор (matches:write) | Просмотр, создание, полное обновление, удаление матчей |

## Сущности

### Match (матч)

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `id` | string (`^[0-9]+$`) | Да | Идентификатор, readOnly |
| `name` | string | Да | Название матча |
| `game` | enum (`Dota 2`, `CS 2`, `Overwatch 2`) | Да | Игра |
| `startDate` | string (`date-time`) | Да | Дата начала |
| `team1` | Team | Да | Первая команда |
| `team2` | Team | Да | Вторая команда |
| `status` | enum (`not started`, `in progress`, `finished`) | Да | Статус матча |
| `events` | array of GameEvent | Да | Связанные игровые события |

### GameEvent (игровое событие)

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `id` | string | Да | Идентификатор, readOnly |
| `name` | string | Да | Название |
| `score` | string (pattern `^\d+:\d+$`) | Да | Счёт `"{team1 score}:{team2 score}"` |
| `coefficient` | number (`double`) | Да | Коэффициент |
| `status` | enum (аналог статуса матча) | Да | Статус события |

### Team (команда)

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `id` | string | Да | Идентификатор, readOnly |
| `name` | string | Да | Название |
| `description` | string, `maxLength: 200` | Нет | Краткое описание |

**Ограничение:** описание команды не более 200 символов [source:21xe3tjr89y600uoauz7].

## Операции

| Ресурс | Метод | Роль | Успех | Ошибки |
| --- | --- | --- | --- | --- |
| `/matches` | GET | Клиент, Админ | 200 | 400, 401, 500 |
| `/matches` | POST | Админ | 201, 409 | 400, 401, 500 |
| `/matches/{matchId}` | GET | Клиент, Админ | 200 | 400, 401, 404, 500 |
| `/matches/{matchId}` | PUT | Админ | 200 | 400, 401, 404, 500 |
| `/matches/{matchId}` | DELETE | Админ | 200 | 400, 401, 404, 500 |

## Пагинация и фильтрация списка матчей

- `GET /matches`:
  - `limit`: integer, `minimum: 1`, `maximum: 100`, `default: 20`
  - `offset`: integer, `minimum: 0`, `default: 0`
  - `game`: enum (`Dota 2`, `CS 2`, `Overwatch 2`)
  - `teamId`: string
  - `search`: произвольный текст поиска по названию матча или команды

- Верхнеуровневый ответ коллекции — объект `MatchList` (`items`, `total`, `limit`, `offset`), не массив.

## Идемпотентность создания

- При `POST /matches` используется заголовок `Idempotency-Key` (UUID).
- Повторный запрос с тем же ключом не создаёт дубликат, возвращается `409 Conflict` с исходным матчем [source:1s5r4vz4tbmt6a0pnxnr].

## Соглашения по данным

- Идентификаторы строковые с префиксами типа (в этом сервисе — числовые строки `^[0-9]+$`, но можно ввести префиксы, например `m_`).
- Временные метки ISO8601 UTC с `Z`.
- Каталог игр — ровно три значения enum.
- Статус матча и игрового события — enum с тремя состояниями.
- Модель запроса (`MatchInput`) содержит `name`, `game`, `startDate`, `team1Id`, `team2Id`, но не содержит `id`, `status`, `events` — их задаёт сервер.
- Модель ответа (`Match`) содержит полные команды `Team` и список `GameEvent`.

## Безопасность

- Схема: OAuth2.
- Scopes:
  - `matches:read` — просмотр списка и одного матча;
  - `matches:write` — создание, обновление, удаление.
- Для защищённых методов обязателен ответ `401 Unauthorized`.
- Все методы защищены scope, так как клиент — роль, а не анонимный пользователь.

# 3. orderService — API платформы заказов

## Бизнес-контекст

`orderService` — API интернет-магазина для управления заказами. Покупатели создают заказы и просматривают историю своих покупок. Администраторы управляют статусами заказов.

## Роли

| Роль | Права |
| --- | --- |
| Покупатель | Просмотр своих заказов, просмотр одного заказа, создание заказа |
| Администратор | Просмотр всех заказов, просмотр одного, изменение статуса, отмена заказа |

## Сущности

### Order (заказ)

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `id` | string (`^ord_[0-9]+$`) | Да | Идентификатор заказа, readOnly |
| `customerId` | string (`^cst_[0-9]+$`) | Да | Идентификатор покупателя |
| `items` | array of OrderItem | Да | Позиции заказа |
| `status` | enum (`created`, `paid`, `shipped`, `delivered`, `cancelled`) | Да | Статус заказа |
| `totalPrice` | number (`double`, `minimum: 0`) | Да | Итоговая сумма, readOnly |
| `createdAt` | string (`date-time`, ISO8601 UTC с `Z`) | Да | Дата создания, readOnly |

### OrderItem (позиция заказа)

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `productId` | string (`^prd_[0-9]+$`) | Да | Идентификатор товара |
| `quantity` | integer (`minimum: 1`) | Да | Количество |
| `unitPrice` | number (`double`, `minimum: 0`) | Да | Цена за единицу |

## Операции

| Ресурс | Метод | Роль | Успех | Ошибки клиента | Ошибки сервера |
| --- | --- | --- | --- | --- | --- |
| `/orders` | GET | Покупатель | 200 | 400, 401, 403 | 500 |
| `/orders` | GET | Администратор | 200 | 400, 401, 403 | 500 |
| `/orders` | POST | Покупатель | 201, 409 | 400, 401, 403 | 500 |
| `/orders/{orderId}` | GET | Покупатель, Админ | 200 | 400, 401, 403, 404 | 500 |
| `/orders/{orderId}/status` | PATCH | Админ | 200 | 400, 401, 403, 404, 409 | 500 |
| `/orders/{orderId}/cancel` | POST | Админ | 200 | 400, 401, 403, 404, 409 | 500 |

## Пояснения по операциям

### Список заказов

- Покупатель вызывает `GET /orders` без `customerId` — сервер определяет идентичность из токена.
- Администратор может передать `customerId` как фильтр и получить заказы конкретного покупателя или всех сразу.
- Поле `status` доступно как фильтр для обеих ролей.

### Создание заказа

- Тело запроса содержит только `items`.
- `customerId` берётся из токена.
- `status` сервер присваивает `created`.
- `totalPrice` сервер вычисляет по позициям.
- `createdAt` сервер присваивает текущую дату.
- `id` сервер генерирует.

Идемпотентность:

- Заголовок `Idempotency-Key` обязателен.
- Повторный запрос с тем же ключом возвращает `409 Conflict` с исходным заказом [source:1s5r4vz4tbmt6a0pnxnr].

### Изменение статуса

- `PATCH /orders/{orderId}/status` — администратор передаёт только новый статус.
- Недопустимый переход статуса (например, доставленный заказ в `paid`) возвращает `409 Conflict`.

### Отмена заказа

- `POST /orders/{orderId}/cancel` — отдельное бизнес-действие.
- Переводит заказ в `cancelled`.
- Если отмена невозможна, возвращает `409 Conflict`.

## Пагинация и фильтрация

- `GET /orders`:
  - `limit`: integer, `minimum: 1`, `maximum: 100`, `default: 20`
  - `offset`: integer, `minimum: 0`, `default: 0`
  - `status`: `OrderStatus`
  - `customerId`: string (`^cst_[0-9]+$`), только для администратора

## Соглашения по данным

- Идентификаторы строковые с префиксами типа:
  - `ord_` — заказ;
  - `prd_` — товар;
  - `cst_` — покупатель.
- Временные метки ISO8601 UTC с `Z`.
- Модель запроса (`RequestCreateOrder`) содержит только `items`.
- Модель ответа (`ResponseOrder`) содержит полный набор полей с `readOnly` для серверных данных.
- Верхнеуровневый ответ коллекции — объект `OrderList` с полем `items`, не массив [source:1s5r4vz4tbmt6a0pnxnr].

## Безопасность

- Схема: OAuth2.
- Scopes:
  - `orders:read` — просмотр заказов (покупатель только своих, администратор всех);
  - `orders:create` — создание заказа (доступно покупателю);
  - `orders:write` — изменение статуса и отмена (доступно администратору).
- `403 Forbidden` используется для разграничения доступа к чужим ресурсам и ограничения прав по ролям.
- Для защищённых методов обязателен ответ `401 Unauthorized`.
